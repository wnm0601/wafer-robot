# 첫 구동용 수동조작 코드 — 모터 비활성 준비판

작성일: 2026-09-30. 현재 상태는 **가상시험 전용**입니다. Arduino 업로드·실제 모터 출력·COM 연결은 하지 않습니다.

현재 기본 실행 창은 [펌웨어 기반 지도 주행 모의환경](23_FIRMWARE_MAP_SIMULATOR.md)으로 업데이트했습니다. 아래는 초기 수동 입력 준비판과 당시 검증 기록입니다. 최신 지도·지점 설정·속도 조절과 실제 C++ 제어 소스 연동은 23번 문서를 확인하세요.

## 조작 계약

- 개별 모드: M1~M4 중 하나를 선택하고 `↑`/`↓`를 누르는 동안만 해당 모터의 가상 M 명령을 보냅니다.
- 4륜 모드: `W/S` 전후, `A/D` 횡이동, `Q/E` 회전의 가상 V 명령을 누르는 동안 보냅니다. 지금의 4륜 매핑은 **가짜 장치 안에서만 검증된 값**입니다.
- `수동 준비`를 먼저 누른 후 키를 눌러야 ARM과 첫 명령을 함께 보냅니다. 키만 눌러서는 시작하지 않습니다.
- 키 해제, 창 포커스 이탈, 모드·모터 변경, Space에서는 STOP을 보내고 수동 준비를 취소합니다. 자동 ARM/자동 재출발은 없습니다.
- X는 소프트웨어 ESTOP 모의입니다. 통신 오류·전원 오류·비상정지 뒤에는 잠기며 이 창에서 자동 복구하지 않습니다.
- 가상 명령값 1~30%는 실제 승인된 전류·토크·속도 상한이 아닙니다. 정지 중에만 변경합니다.

실행: 저장소 폴더에서 `py -3.13 scripts\manual_first_drive.py`. 창 없이 왕복 명령 확인: `py -3.13 scripts\manual_first_drive.py --smoke`.
`--port`는 실제 serial을 열기 전에 거부합니다. 기존 `V/STOP` 방식의 `keyboard_drive`와 새 `C2` 방식은 혼용하지 않습니다.

## 실제 출력 전에 아직 필요한 것

1. 배터리 팩 수·코일 전원, BMS·실측 전압, 전선·퓨즈·극성·접지 및 비상정지 차단을 담당자가 확인해야 합니다.
2. PCB-C/A8 전원 상태 신호와 리셋 중 PWM 핀 상태, 모터별 바퀴·encoder 매핑을 확인해야 합니다.
3. 실제 사용 펌웨어와 gateway를 동일한 C2 버전으로 맞추고, 전원 피드백·GPIO 출력·실제 serial 경로를 별도 검증해야 합니다.
4. 저속 명령·전류·정지 시간을 실제 바퀴가 지면과 분리된 조건에서 담당자와 측정해 승인해야 합니다. 10%, 25%, 30% 중 어떤 값도 현 상태에서 실차 승인값이 아닙니다.

현재 [Mega 소스](../firmware/mega_cart/src/main.cpp)는 PWM 출력 LOW와 `HARDWARE_LOCKED` 상태를 유지합니다. [Python gateway](../src/wafer_cart_keyboard_drive/wafer_cart_keyboard_drive/bench_gateway.py)는 물리 COM을 열지 않습니다. 이 문서와 모의시험이 실제 출력 승인이나 하드웨어 안전성 검증을 대신하지 않습니다.

## 2026-09-30 모터 비활성 확인

- 전체 Windows Python 모의시험과 새 `--smoke` 통과. 새 화면은 `tkinter` 8.6 사용 가능 확인, 실제 창의 시각·키보드 조작은 별도 육안 검증 전입니다.
- `--port COM_DO_NOT_OPEN`은 시작 전에 거부됨을 확인했습니다.
- `mega_locked` 펌웨어 **컴파일만** 성공. Arduino 업로드·실제 PWM 출력은 확인하지 않았습니다.
- WSL 호스트 계약 시험 64건과 Python/C++ 응답 계약 13건 통과. GPIO·serial 장치는 열지 않았습니다.

## 2026-09-30 실제 Windows 창 확인

- `design-verified-ui` 기준으로 Tk 창을 실제 사용자 데스크톱에서 열어 1172×858 캡처에서 한글, 두 모드, M1~M4, 수동 준비·정지 버튼이 보이고 화면 잘림이 없음을 확인했습니다. 다른 DPI·최소 창 크기는 아직 확인하지 않았습니다.
- 실제 창에서 M1 전진, M2 역방향, M3 전진, M4 역방향을 선택·입력했습니다. 각각 최근 가상 M 명령이 표시되고 키 해제 뒤 정지 상태가 표시됐습니다.
- 4륜 모드에서는 수동 준비 전 `W`가 새 명령을 만들지 않았고, 준비 후 `W/S/A/D/Q/E`의 가상 V 명령과 키 해제 뒤 정지 상태를 확인했습니다.
- 첫 화면 확인에서 짧은 키 입력이 50ms 주기 사이에 누락되는 문제를 발견해, 키를 누르는 이벤트에서 즉시 `step()`을 호출하도록 수정하고 같은 실제 창에서 재확인했습니다.
- 화면 검증은 키 입력·표시 및 모의 통신에 한정됩니다. 키를 지속해서 누른 시간·실제 바퀴 회전·접촉기 차단은 검증하지 않았습니다.
