# 같은 화면의 수동 제어와 실측 검증 준비

업데이트: 실제 PWM·COM 수동 코드가 추가되었습니다. 아래는 이전 준비 단계 기록입니다. 최신 상태·실행 조건은 [25_MANUAL_OUTPUT_CONNECTION.md](25_MANUAL_OUTPUT_CONNECTION.md)를 먼저 확인하세요. 실물 업로드·구동·실측은 아직 하지 않았습니다.

작성일: 2026-09-30. 실제 모터 구동·COM 접근·Arduino 업로드는 하지 않았습니다.

## 이번 구현

`py -3.13 scripts\manual_first_drive.py`로 기존 지도·대차·키보드/버튼 조작 화면을 실행합니다.

- `실차 연결 준비`: 현재 출력 잠금과 해결할 항목을 표시합니다. COM 입력은 준비용이며 포트 확인 버튼도 포트를 열지 않습니다. 실제 연결 기능이 활성화되었다는 뜻이 아닙니다.
- `실측 오차 기록`: 정지 상태의 가상 결과를 고정하여 실제 시험의 이동 경로 길이(m) 또는 시작 대비 순 방향 변화(deg)와 비교·저장합니다. 같은 속도·명령·유지 시간·종료 조건으로 시험해야 의미가 있습니다. 각도는 -180~180도이며 여러 바퀴 누적 회전은 지원하지 않습니다.
- 오차는 `가상값-실측값`, 상대 오차는 실측값 절댓값 기준입니다. 실측 0에서는 상대 오차를 계산하지 않습니다. 빈 입력·NaN·무한대·음수 경로 길이·빈 측정 출처를 거부합니다.
- `data/manual_measurement_comparisons.json`에 출처, 반복 횟수, 당시 가상 모델과 소스 SHA, 결과를 저장합니다. 로컬 기록은 Git에서 제외합니다. 직접 입력한 비교 기록일 뿐 자동 교정이나 하드웨어 출력 승인이 아닙니다.
- `ManualControlSession`을 분리하여 모의 환경과 향후 검증된 실차 gateway가 동일한 `ManualFirstDrive`를 사용하도록 구성했습니다. 실차 활성 transport와 실제 PWM HAL은 아직 남아 있습니다. 가상 plant의 좌표를 실차 위치로 표시하면 안 됩니다.

## 확인된 실측과 아직 비어 있는 값

현재 실제 측정값이 새로 입력되지는 않았으므로 실제 이동거리·회전각 오차는 **미검증**입니다. 기존 `measurements.json`의 바퀴 지름·wheelbase·track·네 encoder CPR/부호·바퀴 매핑·센서 TF는 비어 있습니다. 이를 임의 값으로 채우지 않았습니다.

기존 `reference_measurements.json`에는 과거 x1 엔코더 후보(ROS FL/FR/RL/RR 순서 931.8/942.8/874.0/906.6 count/rev), CAD 외곽과 허브 축 참고값이 있습니다. 과거 핀/채널 묶음은 새 HKX PCB와 다르고 M4 원기록의 불일치도 있어서 현재 실물 재검증 없이 적용하지 않습니다. CAD 허브 축 위 점을 바퀴 접지 중심 또는 track으로 사용하지 않습니다. 테이블 1800mm는 사용자 제공값이며 나머지 현장 거리는 사진에서 추정하지 않습니다.

실측 순서:

1. 전원 차단·받침대 상태에서 M1~M4 바퀴 위치를 표시하고, 각 바퀴를 손으로 정확히 5회전시켜 count 변화/5와 부호를 기록합니다. 최소 3회 반복하고 x1 decoder인지 확인합니다.
2. 실제 바퀴 지름, 앞뒤 및 좌우 바퀴 중심 간격, 최종 케이스 포함 외곽, 카메라/LiDAR 장착 위치를 측정합니다.
3. 전원·차단·피드백 확인 후 별도 승인된 저속 시험에서 명령 %, 유지 시간, 전압, 하중, 실제 경로 길이·방향 변화·정지거리를 기록합니다. 순방향/역방향/횡이동/회전을 구분합니다.
4. 화면 비교 기록으로 오차를 확인하고 여러 조건을 반복한 뒤 운동 모델 및 odom 교정값을 결정합니다. 단일 시험 결과를 모든 PWM 구간에 선형 적용하지 않습니다.

## 연결만 하면 주행되는 상태인가요?

아직 아닙니다. 현 단계에서는 아래 조건 없이 실차 출력을 열 수 없습니다.

- Mega `main.cpp`는 출력 잠금, 실제 PWM 출력 HAL 미활성이고 power feedback은 미확정입니다.
- 배터리 실제 전압, 코일 전원 구성, 보호 전선/퓨즈, E-Stop 차단 및 재무장 시험이 필요합니다.
- A8 피드백 회로/극성, 현재 PCB의 바퀴 매핑·모터/encoder 부호를 확인해야 합니다.
- 실제 출력 상한과 저속 시험 조건을 확인한 후 수동 전용 firmware/serial gateway 경로의 구현·업로드·현장 검증이 필요합니다.

기존 30%는 과거 소프트웨어/가상 제한이지 새 배터리 구성의 승인 출력 상한이 아닙니다. 준비 체크박스나 저장된 boolean으로 출력 승인을 대체하지 않습니다. 실차 연결이 완성된 뒤에도 준비 → 누르는 동안 이동 → 해제/창 전환/통신 오류 정지 → 명시적 재준비 흐름을 유지합니다. 소프트웨어 정지는 하드웨어 전원 차단을 보장하지 않습니다.

## 현재 검증

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\run_firmware_simulator_checks.ps1 -UI`를 실행합니다. Python 76건, PC의 실제 C++ Controller 기반 주행·encoder·충돌·timeout·ESTOP, 실제 Tk 누름/해제·정지 및 두 대화상자 표시를 검사합니다. Tk 실측 입력/저장 시험은 `data/output/measurement_ui_fixture.json`에 합성 시험값으로만 기록하여 사용자 실측 기록과 분리합니다.

현재 실행 결과는 `data/output/manual_simulator_current.json`과 `manual_simulator_ui_current.json`에 남깁니다. 이전 보고서의 성공을 현재 실차 시험 결과로 취급하지 않습니다.
