세 도구의 동작을 공통 모듈로 묶어 동일한 오류가 각각 재발하지 않게 했습니다.
단일 모터 속도 범위는 기존 5~100에서 5~40으로 줄였고, 세 도구의 기본값은 10으로 통일했습니다.
카운트 리셋 Z/C 기능은 단일 시험에서 제거했습니다. ENC는 자동 기록하며 방향은 관찰로 판단해야 합니다.

## 중요한 한계와 변경하지 않은 사항

1. **퓨즈 미장착이면 전원 투입 전 보완해야 합니다.** 바퀴를 들었다고 배선 단락·과전류가 보호되지는 않습니다. 정격은 배터리·배선·드라이버·시동전류에 맞게 확인해야 하며 이 문서는 임의의 퓨즈 정격을 확정하지 않습니다.
2. `PWR_SENSE_ENABLED=false`는 그대로입니다. 현재 구성에서 접촉기/물리 비상정지를 소프트웨어가 감지했다고 표시할 수 없습니다. `PWR DISABLED`는 “전원 정상”이 아닙니다.
3. 펌웨어는 ENC A만 세고 부호는 명령 방향으로 붙입니다. B상 방향 검증도, 실제 회전 방향 측정도 아닙니다. ROS odometry에 그대로 넣지 마십시오.
4. 펌웨어에는 엔코더 무변화에 따른 스톨 차단이 없습니다. ENC가 반복해서 0이어도 센서 단선인지 실제 정지인지 구별하지 못합니다. 수정 도구도 이를 실제 정지로 보증하지 않습니다.
5. 기존 펌웨어의 1.5초 통신 타임아웃과 감속은 유지했습니다. 목표 0 설정 이후 램프 감속 시간이 추가됩니다. 이는 키 해제 시의 STOP 동작과 별개입니다.
6. `ESTOP`은 이 펌웨어에서 즉시 출력 0 명령이지 물리 차단이나 영구 잠금이 아닙니다. 다음 유효 명령을 막는 펌웨어 래치는 추가하지 않았습니다. 수정 시험 도구는 오류 후 세션을 종료합니다.
7. 40은 실제 속도 40%가 아닙니다. `MAX_DUTY=200`이므로 40 명령은 듀티 80/255, 약 31.4%입니다. 이는 전류 제한이 아닙니다. PWM은 약 3,906.25Hz입니다.
8. Windows 창 단위 포커스 검사입니다. 같은 VSCode 창 안의 에디터/통합 터미널 포커스는 구별하지 못합니다. 실물 시험에는 전용 독립 터미널 창을 사용하고 다른 편집을 병행하지 마십시오. 이번에는 실제 키보드·USB 지연을 시험하지 않았습니다.
9. 프로토콜에 명령별 순번/CRC가 없습니다. ACK를 받아도 실제 핀 전압이나 회전 성공을 의미하지 않습니다. ROS/자동 운전 통합 전에 별도 검토가 필요합니다.
10. 다른 기존 카메라 추종 도구는 새 공통 수동 실행부를 거치지 않습니다. 그 도구의 안전성까지 개선됐다고 보아서는 안 됩니다.

수정 Python은 `--port`를 반드시 지정하도록 바꿨습니다. COM3/COM7은 임의 확정하지 않습니다.
공유된 오래된 `git checkout ... && git pull` 명령도 사용자 수정이 있는 원래 폴더에서 그대로 실행하지 마십시오.
