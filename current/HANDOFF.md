# 최신 대차 코드 인수인계

## 1. 작업 목표

정상 구동 모터 코드를 보존하면서 최신 UI와 카메라/LiDAR 화면 점검 코드를 재실행할 수 있도록 정리했습니다. 다음 초점은 무구동 동일 표적·거리 검증입니다.

## 2. 현재 환경

wnm0601/wafer-robot main, Windows Python 3.13 기준입니다. 상세 패키지는 requirements-ui.txt/requirements-vision.txt를 읽으세요. 기존 PC 작업 루트는 C:/Users/H/Desktop/로봇 자율주행입니다. 신규 PC 장치 번호/설치/GPU는 재확인해야 합니다.

## 3. 현재까지 완료된 작업

수동/시간/버튼형 순서 UI, 6방향 시간·출력 설정, CSV·창 녹화·정적 CAD, YOLO 중앙 오차, 카메라+LiDAR 점검, 회색 판 학습 준비 코드를 current/에 정리했습니다. 158개 단위 검사와 계산 5항목 결과는 STATUS.md를 확인하세요.

## 4. 관련 파일·폴더·브랜치와 권장 읽기 순서

루트 README → USAGE.md → MODELS.md → STATUS.md → SOURCE_MANIFEST.json → 각 모듈 README 순서입니다. current/ROBOT-motor-review-928b2a8은 전체 upstream clone이 아니라 필요한 보존 파일만 복사한 폴더입니다. 과거 루트 START.cmd는 최신 진입점이 아닙니다.

## 5. 현재 문제 또는 막힌 점

공개 배포에는 .pt가 없으므로 별도 복원이 필요합니다. 카메라와 LiDAR가 같은 상자를 보는지, 50cm대 거리가 상자인지 원통인지 미검증입니다. 아래로 보는 카메라는 기존 직립 전후 안내의 검증 범위 밖입니다. 회색 판 실제 데이터는 없습니다.

## 6. 다음 담당자가 해야 할 작업과 추천 스킬

codebase-understanding으로 실행 경로를 먼저 확인하고 computer-use로 무구동 센서 화면을 점검하세요. 상자만 치웠다 놓기 → 독립 거리/이동량 실측 → 센서 보정 순으로 진행합니다. UI 변경 요청이 있을 때만 design-verified-ui를 적용하고 모터 코드와 분리하세요.

## 7. 절대 건드리면 안 되는 것과 승인 필요 작업

정상 모터 main.cpp/common/manual_motor_test.py/driver_adapter.py를 임의 수정하지 마세요. GitHub 정리는 실제 모터 구동이나 업로드 승인이 아닙니다. 모터 시험/Arduino 업로드/배선 변경은 당시 전원·안전 상태와 사용자 요청을 다시 확인합니다. 전원 감시 false, B상 미사용을 숨기지 마세요. 기존 원본/과거 작업·Git 이력을 지우지 않습니다.

## 8. 원하는 결과물 형식

한국어 존댓말, 사실/추정/미검증 구분, 재현 명령과 시험 날짜를 기록합니다. Markdown UTF-8 BOM, Python UTF-8, 실제 파일 존재·인코딩·VSCode 표시를 확인합니다. 공개 저장소에 사진·로그·학습 데이터·가중치·비밀정보를 추가하지 마세요.

## 9. 검증 기준과 남은 위험

코드 검사는 USAGE.md의 무구동 테스트로 재현합니다. 모델/카메라/serial은 가짜 또는 합성 입력으로 검사하므로 실물 정확도와 분리합니다. 시간 주행은 폐루프가 아니며 배터리·바닥·하중에 따라 달라집니다. UI 정지는 물리 차단을 대체하지 않습니다.

## 10. 바로 복사할 최종 프롬프트

“wafer-robot/current의 README·USAGE·STATUS·MODELS·SOURCE_MANIFEST를 먼저 읽어 주세요. 정상 모터 코드는 수정하거나 구동하지 말고, 센서 화면에서 빨간 상자만 치웠다 놓을 때 카메라와 LiDAR가 같은 표적을 보는지 검증 준비를 해 주세요. 관측과 가정을 구분하고 사용자에게 준비 순서를 안내한 뒤 확인해 주세요.”
