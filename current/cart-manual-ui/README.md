# 대차 수동 제어 UI

정상 구동 원본은 수정하지 않습니다. 이 폴더만 추가했습니다.
Windows Python 3.13/Tkinter로 기존 통합 화면의 상단 원형 웨이퍼, 좌우 지도·카메라, 하단 조작 배치를 재구성했습니다.

## 주행별 시간 측정 · 6방향 (2026-10-14)

`start-ui.cmd` 실행 → `키보드 수동` → `주행별 시간 · 6방향` 탭을 사용합니다. 기존 창은 정지·연결 종료 후 다시 실행해야 반영됩니다.

- W 직진 / S 후진 / A 좌회전 / D 우회전 / Z 왼쪽 평행 / C 오른쪽 평행을 각각 키나 화면 버튼 하나를 누르는 동안 측정합니다.
- 놓으면 기존 정지 절차를 실행하며, 방향별 마지막 명령 시간·출력 %·모의/실차·종료 사유를 유지합니다. 같은 방향을 다시 누르면 새 구간을 측정하고 이전 구간은 최근 500건 기록에 남습니다.
- 측정 탭의 `측정 출력 (%)`에서 5~40%를 5% 단위로 선택한 뒤 `정지 중 적용`을 누릅니다. `현재 적용` 값이 바뀐 것을 확인하고 주행하세요. 선택만으로는 적용되지 않으며 출력 적용만으로는 출발하지 않습니다. 6방향 공통 출력이며 방향마다 정지 후 다시 설정할 수 있습니다. 하단 +/- 조절도 유지됩니다. 순서 주행은 기존대로 20% 고정입니다.
- 수동 모드의 미연결/입력 대기 상태에서만 적용할 수 있습니다. 주행·정지 대기·연결 중 또는 주행 키를 누른 상태에서는 변경을 차단합니다. 변경 요청은 UI 통신 작업 스레드에서 기존 5% 조절 함수를 사용하며 펌웨어·원본 제어 코드는 그대로입니다.
- 연결 종료 후 `CSV 저장`을 누르면 `logs/travel_*.csv`에 저장합니다. `주행방향` 열로 6방향을 구분합니다. 정상 앱 종료 시에도 미저장 기록을 저장하지만 강제 종료 시 유실될 수 있습니다.
- 명령 상태를 UI에서 관찰한 시간이며, 물리적인 움직임 시작·완전 정지 시간이나 실제 거리·각도를 자동 측정하지 않습니다. 실측값의 자동 보정·순서 적용은 추가하지 않았습니다.
- 펌웨어, 원본 `manual_motor_test.py`, `driver_adapter.py`는 변경하지 않았습니다. 변경 전 UI·기록기는 `backups/all-motion-timing-20261014-180024/`에 보관했습니다.

검증: `python -B -m unittest -v test_travel_log test_adapter` 39개 통과, `python -B -m unittest -v test_timed_drive` 48개 통과(총 87개, 두 실행으로 검증). 6방향 버튼의 모의 명령·해제·시간 유지, 창/탭 전환, CSV 방향 구분, 기존 순서 주행·회전·녹화, 제어 명령 비변경을 확인했습니다. 실제 모터 시험은 하지 않았습니다. 아래 이전 검증 기록의 실패는 당시 실행 결과이며 이번 두 실행은 모두 통과했습니다.

## 통합 메인: 버튼형 순서 주행과 화면 녹화

출력 선택 추가 후 검증(2026-10-14): `python -B -m unittest -q test_travel_log test_adapter test_timed_drive` 88개 통과. 미연결/모의 연결 출력 적용, 범위 오류·주행 중 변경 차단, 실제 Windows 화면의 현재 적용값 갱신을 확인했습니다. 실제 COM 연결·모터 구동은 하지 않았습니다. 변경 전 파일은 `backups/timing-output-20261014-180945/`에 보관했습니다.

`start-ui.cmd`가 통합 메인 화면을 실행합니다. 이미 열린 구버전 창에는 변경이 반영되지 않으므로 정지·연결 종료 후 다시 실행하세요.

1. 미연결 상태에서 `순서 주행 20%`를 선택합니다. 연결 중에는 조작 방식을 바꿀 수 없습니다.
2. `동작 순서 · 버튼으로 추가` 탭에서 직진/좌회전/우회전/왼쪽 평행/오른쪽 평행을 선택하고 `＋ 동작 추가`를 누릅니다. 직진은 m, 회전은 도, **평행이동은 직접 지정한 초(0.5~60)**를 입력합니다. 예: `직진 1m → 오른쪽 평행 2초 → 좌회전 90도`. 각 구간은 서로 다른 시간을 지정할 수 있습니다.
3. 목록 선택 후 위/아래로 옮기거나 삭제합니다. 작은 창에서는 오른쪽 세로 스크롤로 아래 조작을 확인하세요.
4. `입력 검사 / 시간 환산`으로 구간별 시간과 총시간을 확인합니다. 목록·초/m 변경 시 다시 검사해야 합니다.
5. 우선 모의 연결 후 `전체 순서 실행 · 20%`로 확인합니다. 실차 연결은 안전 조건과 원본 펌웨어 확인을 별도로 거칩니다.
6. 각 구간은 ESTOP/STOP 응답과 ENC 정지 대기 후 다음 구간으로 넘어갑니다. 실제 정지 검증을 대신하지 않습니다. Space·창 이탈·탭 전환·통신 오류·연결 종료는 남은 순서를 취소하며 자동 재개하지 않습니다.

거리 기준은 기본 약 8.54371초/m, 회전은 사용자가 확인한 20% 45도=1초를 비례 적용합니다. 바닥·하중·배터리 상태에 따라 오차가 나며 실제 거리/각도 도착이나 장애물 회피를 보장하지 않습니다. 직진 0.1~5m(구간 시간 0.5~60초), 회전 5~180도, 최대 20구간, 구동 합계 120초 이내입니다. 정지 대기 시간은 합계와 별도입니다.

평행이동도 출력은 20% 고정이며 전체 20구간/구동 합계 120초 제한에 포함됩니다. 좌/우는 원본 Z/C 명령을 사용합니다. 입력 시간으로 실제 거리를 보장하지 않으며 1m 측정 기록을 자동 적용하지 않습니다.

수동 주행은 `키보드 수동` 모드의 `대차 최종본 · 주행 기록` 또는 `주행별 시간 · 6방향` 탭에서 기존 방식으로 사용합니다. 편집 탭에서는 수동 키보드 명령을 차단합니다. 같은 연결 작업 스레드가 포트 하나를 소유하므로 시간 앱이나 기존 터미널을 동시에 연결하지 마세요.

순서 기록은 메모리에 모았다가 연결 종료 또는 앱 정상 종료 시 `logs/sequence_*.csv`로 저장합니다. 구간 번호, 요청 거리/각도, 명령 시간, 원시 ENC와 정지 응답 여부가 들어갑니다. 강제 종료 전에는 연결 종료로 저장하세요. 구간 기록은 실제 경로 완주의 증거가 아닙니다.

오른쪽 위 `화면 녹화 시작`을 누르면 이 앱 창만 녹화합니다. `녹화 중지 / 저장`을 누르면 `recordings/cart_screen_*.avi`에 저장하고 하단에 파일명을 표시합니다. 무음 MJPG AVI, 기준 5fps, 최대 30분입니다. 마이크/데스크톱 전체를 녹화하지 않습니다. 창 크기가 바뀌면 원래 영상 크기에 맞춰 여백을 넣습니다. 최소화·창 닫힘·캡처 실패 시 녹화를 종료하며 가능한 기존 프레임은 저장합니다. 강제 종료·저장 장치 오류 시 정상 영상 저장을 보장하지 않습니다.

녹화 의존성: 이 환경에서 확인된 Pillow 12.2.0(window capture 지원), OpenCV 4.13.0, NumPy. 없거나 지원하지 않으면 녹화 오류를 표시하고 전체 데스크톱 캡처로 대체하지 않습니다. 녹화/파일 쓰기는 통신 스레드 및 Tk 입력 루프 밖에서 실행하지만, PC 전체 부하로 응답 시간이 늘면 주행 정지 보호가 작동할 수 있습니다.

전체 모의 검증: `python -B -m unittest discover -v` (이 폴더에서 실행). 실제 COM 포트는 열지 않습니다.

## 주행 시간 기록 (2026-10-12 추가)

### 평행이동 시간 탭 (메인 UI)

`start-ui.cmd`로 메인 UI를 실행하고 **키보드 수동 → 주행별 시간 · 6방향** 탭을 선택합니다. 기존 평행이동 시간 탭을 확장한 화면입니다. 별도 `start-timed-ui.cmd` 화면은 변경하지 않았습니다.

1. 연결 후 입력 대기 상태에서 출력 − / +로 20%를 맞춥니다. 시험 전 현장의 공간과 물리 차단 수단을 확인합니다.
2. `Z 왼쪽 평행` 또는 `C 오른쪽 평행` 버튼/키 하나를 누르는 동안 이동 명령과 경과 시간을 표시합니다. 키/버튼을 놓으면 기존 제어 코드의 정지 절차로 전환합니다. 버튼 밖으로 이동하거나 창·탭을 전환해도 정지합니다.
3. 좌·우 마지막 구간의 모드, 출력%, 시간을 각각 유지합니다. 시간은 UI 명령 상태 관찰 기준이며 실제 이동·정지 시점이나 자동 거리 측정이 아닙니다.
4. 실차 20%에서 직접 표시해 둔 1m를 이동한 경우에만, 정지 후 `방금 이동을 실제 1m로 확인`을 누르고 확인합니다. 미확인·모의·다른 출력·오류/연결 종료된 구간은 실제 1m 보정값으로 기록하지 않습니다. 다음 움직임을 시작하면 이전 구간의 확인 대상을 폐기합니다.
5. 연결 종료 후 탭의 `CSV 저장`으로 `logs/travel_*.csv`를 저장합니다. CSV의 `평행방향`, `사용자확인초_m` 열로 좌·우 기록을 구분합니다. 확인값은 이번 실행 동안 표시하며 재실행 시 불러오거나 순서 주행에 자동 적용하지 않습니다.

실제 주행 코드는 그대로 사용합니다. 펌웨어, 원본 Python 모터 제어, `driver_adapter.py` 변경 및 실제 구동 검증은 하지 않습니다.

모터 원본과 `driver_adapter.py`는 변경하지 않습니다. `travel_log.py`는 통신 기능 없이 UI가 받은 상태만 관찰합니다.
오른쪽 미연결 카메라 영역에 기록 패널을 배치했으며 실제 영상은 연결하지 않았습니다.

- 주행 명령 구간의 시작·종료 시각, 경과 시간, 명령 비율과 방향, 모의/실차 구분을 자동 기록합니다.

- 실차 모드에서만 사용자가 1m를 확인했다고 기록하고 `1 / 경과초`를 참고 평균으로 표시합니다. 가속 및 사람의 반응 지연이 포함되며 실제 속도를 자동 측정한 결과가 아닙니다.

- 모의 모드는 도착 기록 연습만 가능하며 거리·평균 속도 칸을 비워 저장합니다.
- 최근 완료 기록 500건을 메모리에 유지합니다. **연결 종료 후 CSV 저장**을 누르면 이 폴더의 `logs/travel_*.csv`로 UTF-8 BOM 파일을 저장합니다. 기존 파일을 덮어쓰지 않습니다.
- 정상 앱 종료 시 미저장 기록을 저장합니다. 강제 종료·프로세스 장애·디스크 오류 시 저장을 보장하지 않습니다. 500건을 초과한 오래된 기록은 사라지므로 필요 시 먼저 저장하세요.
